## Task 5 — Batched, numpy-only predict path + caches (Step 3b)
**Files:** predict service module(s), `tests/test_predict_batching.py` (new).

1. Test: `/predict/sweep` calls each booster's `predict` exactly once (spy). Same for `/predict/compare`. Run → fails.
2. Refactor: predict service takes an `(n, f)` numpy array; single predict = n=1; compare = n≤3; sweep = n=12. Remove pandas from the hot path.
3. `pred_contrib=True` only on q50 models.
4. Embedding cache: `lru_cache(maxsize=256)` keyed on `sha1(normalized synopsis)`; empty synopsis → stored zero/default vector exactly as current code does.
5. Response cache: `lru_cache(maxsize=512)` keyed on canonical JSON of the validated request (sorted keys, normalized strings). Add `X-Cache: hit|miss` header. Test: same request twice → second is a hit and identical body.
6. `perf_check.py` (must be identical). Bench throttled → check G1–G3. Log. Commit: `perf: batched numpy predict path, contrib on median only, caches`.

## Task 7 — SQLite and Neon (Step 5)
**Files:** `app/db.py` (or equivalent), `scripts/add_indexes.sql` (new, applied at build), new-arrivals refresh module, accounts DB module.

1. Read-only connection: `sqlite3.connect("file:...?mode=ro&immutable=1", uri=True, check_same_thread=False)` per thread (thread-local), pragmas `mmap_size=268435456`, `cache_size=-20000`, `temp_store=MEMORY`.
2. Write `scripts/explain_queries.py`: runs `EXPLAIN QUERY PLAN` for every hot query with typical parameters, prints any `SCAN` on tables > 10k rows. Add indexes to `add_indexes.sql` until none remain (e.g. `(year)`, `(original_language)`, `(popularity DESC)`, `(vote_average)`, `movie_genres(genre_id, movie_id)`, `movie_cast(person_id)`, `movie_cast(movie_id, cast_order)`). Apply at build time; `ANALYZE` afterwards.
3. N+1: find loops that query per item (grep for queries inside `for` loops in list endpoints) → single `IN (...)` query. Test: browse page issues ≤ 3 queries (count with a connection wrapper in tests).
4. Writable new-arrivals DB: `journal_mode=WAL`, `synchronous=NORMAL`. TMDB refresh → `BackgroundTasks` / `asyncio.create_task` guarded by an `asyncio.Lock` and a "last refreshed" timestamp; user requests always read the current data and never wait for TMDB. Test: request during refresh returns without awaiting the HTTP call (mock with a slow fake).
5. Neon: `psycopg_pool.ConnectionPool(conninfo, min_size=0, max_size=3, open=False)` opened in `lifespan`; use the pooled (`-pooler`) connection string; only account endpoints use it. Existing compose-Postgres tests must pass.
6. Bench throttled → G4. Log. Commit: `perf: sqlite pragmas and indexes, no N+1, background refresh, neon pool`.

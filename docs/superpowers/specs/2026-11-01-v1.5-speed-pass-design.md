# V1.5 Speed pass — design spec

**Date:** 2026-11-01
**Status:** Approved decisions, awaiting spec review
**Placement:** After the V1.4 career work and the Wikidata money experiments, immediately before the deploy session (Render Free)
**Goal:** Make the app as fast and smooth as possible on Render Free (512 MB RAM, 0.1 CPU, spins down after 15 idle minutes) without changing model outputs or features.

---

## 1. Decisions

| # | Decision |
|---|----------|
| D1 | Cold start: uptime monitor pings `/api/v1/health` every 10 min **and** React shows a "Waking up the server…" screen if `/health` hasn't answered within ~2 s. |
| D2 | Scope: all 7 steps. Cut line: frontend step (6) moves to the deploy session if behind. Backend, database and cold-start work are never cut. |
| D3 | Speed targets are **pass/fail gates**, measured in Docker with Render-like limits (`--cpus 0.1 --memory 512m`). |
| D4 | Measure first, change second. A change that doesn't improve its measured number is reverted. |
| D5 | No model changes. Models stay v1. Predictions must be **bit-identical** (or within 1e-9) before and after. |
| D6 | Single uvicorn worker. |

## 2. Gates (pass/fail)

Measured with `docker run --cpus 0.1 --memory 512m` unless marked "local".

| Gate | Target |
|------|--------|
| G1 `POST /predict` p95 (local, unthrottled) | ≤ 400 ms |
| G2 `POST /predict` p95 (throttled) | ≤ 1.5 s |
| G3 `POST /predict/sweep` and `/predict/compare` p95 (throttled) | ≤ 2.5 s |
| G4 Read endpoints (movies list/detail, search, autocomplete, people pages) p95 (throttled) | ≤ 300 ms |
| G5 Container peak RAM during the benchmark | < 450 MB |
| G6 Startup: container start → `/health` 200 (throttled) | ≤ 20 s |
| G7 Lighthouse Performance, mobile, Home + Browse + Movie detail | ≥ 90 |
| G8 Initial JS (gzipped) on the Home route | ≤ 200 KB |
| G9 All existing tests pass; prediction outputs identical to baseline snapshot | 100% |

> The deploy-plan acceptance of "live up to ~3 s" still stands as a worst case; G2 is the target we aim for.

## 3. Work areas

### 3.1 Baseline and measurement (Step 1)
- `ServerTimingMiddleware`: adds `Server-Timing: app;dur=<ms>` and logs slow requests (> 500 ms).
- `scripts/bench.py`: fixed list of requests (3 presets for predict, 1 compare with 3 variants, 1 sweep, browse pages with filters, search queries, 2 actor pages, autocomplete). Reports p50/p95 per endpoint as Markdown. Uses `httpx` with 20 repeats each (no extra tool install needed).
- `scripts/perf_snapshot.py`: saves predict / compare / sweep outputs for the presets to `tests/fixtures/perf_snapshot.json` (used by G9).
- Records: image size, startup time, idle + peak RAM (`docker stats`), Lighthouse scores, bundle sizes → `docs/perf/baseline.md`.

### 3.2 Lean runtime (Step 2)
- Split `requirements-app.txt` (FastAPI, uvicorn, lightgbm, onnxruntime, numpy, tokenizers, psycopg[binary,pool], orjson, httpx, sentry-sdk) and `requirements-train.txt` (`-r requirements-app.txt` plus pandas, scikit-learn, MAPIE, Optuna, matplotlib, jupyter, hypothesis, pytest…). Exact lists come from an import audit of the app package.
- Anything the app imports only from training libs (e.g. MAPIE calibration) is replaced by saved artifacts (conformal offsets as JSON/numbers).
- Multi-stage Dockerfile: Node stage builds React → Python `3.12-slim` stage with wheels only; copies only the app package, databases, model files and `dist/`.
- Remove dead code: earlier New Arrivals live-fetch code, spike leftovers, unused endpoints/functions (found with `vulture` + grep, reviewed by hand before deleting).
- One `build_features()` used by both training and serving. A test checks that serving features equal training features for 50 random films.

### 3.3 Backend (Step 3)
- All heavy objects loaded once in FastAPI `lifespan` into an `AppState`: boosters, ONNX session, tokenizer, comparables matrix, options, model card.
- `OMP_NUM_THREADS=1`, LightGBM `num_threads=1`, ONNX `intra_op_num_threads=1`.
- Predict path uses numpy only (no pandas). Quantile models scored from one feature array. `pred_contrib` only for median (q50) models.
- `/predict/compare` and `/predict/sweep` build one matrix with all rows and call each booster once.
- Synopsis embedding: cached by text hash (LRU 256), skipped when the synopsis is empty.
- `functools.lru_cache`-style cache (size 512) on normalized predict input → full response.
- `ORJSONResponse` as default; `GZipMiddleware(minimum_size=1000)`.

### 3.4 Precompute (Step 4)
At build time (script run before `docker build`, outputs baked into the image):
- Comparables: normalized feature matrix + ids as `.npy` (float32).
- Career stats and track-record forecasts per person → table `person_career_cache`.
- Home rows and filter options → table / JSON.
Served values must equal on-the-fly values (test).

### 3.5 Databases (Step 5)
- Read-only SQLite: `file:...?mode=ro&immutable=1`, `PRAGMA mmap_size=268435456`, `cache_size=-20000`, `temp_store=MEMORY`. One connection per thread, reused.
- `EXPLAIN QUERY PLAN` for every query used by browse, search, movie detail, actor page and home rows; add missing indexes (built into the DB at build time, not at runtime). No `SCAN TABLE` on large tables in hot paths.
- Remove N+1 patterns (e.g. per-card cast queries → one `IN (...)` query).
- Writable new-arrivals SQLite: WAL mode, `synchronous=NORMAL`. TMDB refresh runs as a background task with a lock, never inside a user request.
- Neon: `psycopg_pool.ConnectionPool(min_size=0, max_size=3)` with the pooled connection string. Only account endpoints touch Neon.

### 3.6 Frontend (Step 6, cut line)
- Route-level `React.lazy` + `Suspense` for Predict, Results, Compare, Actor, Account pages. Recharts/chart code only in those chunks.
- `rollup-plugin-visualizer` report saved to `docs/perf/bundle.html`.
- TanStack Query: `staleTime` 10 min for movie/person data, `Infinity` for options/model-card; prefetch movie detail on card hover (desktop only).
- TMDB image sizes: `w185` grids, `w342` small detail, `w500` large detail, `w92` dropdown thumbs; `loading="lazy"`, `decoding="async"`, explicit width/height. First visible row eager.
- Start-page collage converted to WebP/AVIF with `<picture>`.
- Search: 250 ms debounce, abort stale requests (TanStack Query `signal`).
- Cache headers from FastAPI: hashed assets `public, max-age=31536000, immutable`; `index.html` `no-cache`; options/model-card `max-age=3600` + ETag; movie/person detail `max-age=600`.
- `WakeUpGate` component: calls `/health` on load; if no answer in 2 s shows "Waking up the server… this can take up to a minute on the free plan" with a progress hint; retries every 3 s.

### 3.7 After (Step 7)
- Rerun `bench.py`, Docker metrics, Lighthouse with the same settings → `docs/perf/after.md` with a before/after table and gate results.
- Any change without a measurable gain is reverted (D4).
- Short entry in the decision log.

## 4. Out of scope
- Model retraining or tuning.
- Paid hosting, Redis, CDN.
- New features or UI redesigns.

## 5. Risks
| Risk | Mitigation |
|------|-----------|
| Removing a "dead" function that's used dynamically | Full test suite + Playwright flow + smoke script after each deletion batch |
| Train/serve feature refactor changes predictions | G9 snapshot test must pass before moving on |
| Docker `--cpus 0.1` behaves differently on Windows/WSL2 than on Render | Treat throttled numbers as estimates; real check happens in the deploy session |
| ONNX embedding is the slowest step at 0.1 CPU | Text-hash cache; if G2 fails, profile first, then consider truncating the synopsis to 128 tokens (needs approval because it changes outputs) |

# Wikidata Money: More Revenue and Budget Labels (V1.5): Design Spec

Oct 31, 2026 · @Dimitris · Movie Prediction App · **V1.5** (after V1.4, career 2026)

## Goal

Give the revenue model more films with a known worldwide box office, and the budget model more films with a known budget, without letting any unchecked value into `movies.db`:

1. **Fill (option 1):** for the ~79k films already pulled, take budget and worldwide box office from Wikidata where TMDB has none or has a value already flagged as bad.
2. **Targeted pull (option 2):** pull from TMDB the 1960–2025 films that Wikidata says have a box office or budget and that are not in our pull yet.
3. **Cross-check:** where both sources have a value and they disagree by more than 3×, flag the film so it leaves financial training.
4. **Retune, retrain and compare** against today's model on the same films; keep the new data only if revenue improves.

**Success:** more films usable for revenue training; revenue MAE log on validation and backtest lower than v1 on the same films (v1 validation 1.093); revenue coverage 77–83%; budget and score no worse than v1 beyond the backtest std; Docker memory still < ~450 MB.

**Constraints carried over:** fast and simple; one SQLite database for app and ML; "nothing is stored before it is cleaned" (raw → `clean.py` → temp DB → swap); the 2019+ test is run once for v2 and labelled as seen before; TMDB attribution unchanged.

## Why

- **Learning curve (Oct 31, sklearn HistGradientBoosting stand-in, tuned LightGBM settings):** revenue validation error still falling at 100% of training films (55% → 100%: 1.142 → 1.102; ~1.07 estimated at 2× films). Budget gains ~0.01, score has flattened.
- **More films by vote rank won't help:** share of films with usable revenue by rank within year: 1–300 40.1%, 301–600 7.5%, 601–900 3.1%, 901–1,200 1.9%. The next 40k by votes would add roughly 400 revenue films.
- **Bigger models won't help:** ~10k revenue rows; tuning gained ~2% over defaults; synopsis embeddings gave no gain; Render Free memory limit.
- **What is short is labels:** only 10,421 of 79,199 films have usable revenue; Wikidata has box office and budget for many films, with currency and region qualifiers, under CC0.

## Decisions

| Topic | Decision |
|---|---|
| Scope | Fill existing films + targeted pull of films Wikidata says have money (option A) |
| Box office | Worldwide only: a value with the worldwide region qualifier, or the single value when it has no region qualifier. US-only and single-country values ignored |
| Currencies | Convert a fixed list (from a survey of real counts: currencies with ≥ 50 films, plus FRF, DEM, ITL, ESP) at the release year's average rate, then US CPI to 2025 dollars; other currencies dropped |
| FX source | World Bank yearly official exchange rate (LCU per USD), saved as `data/fx_rates.csv` |
| Disagreement | TMDB wins; Wikidata > 3× apart (2025 dollars) → `money_suspect`, reason `wikidata_disagree` |
| New films in the app | Everywhere like any film: Browse, search, actor pages, comparables, track records |
| Architecture | Wikidata to raw files, merged in `clean.py` (approach 1); `money_source` column |
| Keep rule | Decided on validation + backtest only, like for like; Optuna retune before the comparison |
| Name | V1.5 Wikidata money |

## 1. Data flow

```
Wikidata SPARQL (one query per release year 1960–2025)
   └─ ml/data/wikidata.py ──► data/raw/wikidata_money.jsonl   (raw, untouched)
                             data/raw/wikidata_survey.json  (currency and region counts)
World Bank FX ──► data/fx_rates.csv                          (fixed file, like cpi_us_annual.csv)

New TMDB ids (Wikidata money, not in our pull)
   └─ appended to data/raw/discover_ids.csv with page=0 (= from Wikidata)
   └─ pull.py details phase ──► tmdb_movies.jsonl
   └─ people.py             ──► tmdb_people.jsonl

build_db.py ── clean.py (existing + new money rules) ──► temp DB ──► swapped in
   └─ features + synopsis embeddings for new films
retune ─► retrain ─► compare with v1 ─► (keep) test + 2026 holdout ─► model card v2
```

### `ml/data/wikidata.py`

- `survey`: counts box office and budget statements per currency and per region qualifier for films with a TMDB movie id (P4947); writes `wikidata_survey.json`. The currency list in `fx_rates.csv` is fixed from it.
- `pull`: per release year, every box office (P2142) and budget (P2130) statement of films with a TMDB id: TMDB id, Wikidata id, property, amount, unit, rank, region qualifier, point in time. One JSON line per statement. Resumes by year (years already in the file are skipped); one query per year keeps each under the query time limit; descriptive User-Agent; retries with backoff on 429/5xx.
- `new-ids`: TMDB ids in `wikidata_money.jsonl` with a release year 1960–2025 that are not in `discover_ids.csv`; appended as `year,0,id` rows (page 0 marks Wikidata; TMDB discover pages start at 1, so no reader changes).
- The exact region qualifier and worldwide item are confirmed by `survey` before `pull` runs (expected: P3005 "valid in place" = Q13780930 "worldwide").
- Network access runs on Dimitris's PC (Claude Code); the cloud workspace cannot reach Wikidata.

### New films

- Same TMDB details and people pulls as every film; the existing cleaning keeps only status "Released" and 1960–2025 for the models.
- `discover_ids.csv` rows with `page = 0` are the Wikidata films, so the report can count them.

## 2. Cleaning rules (`ml/data/clean.py`)

All run before anything is written; each adds a line to the cleaning report.

### Reading Wikidata statements

- Deprecated rank → skipped. A preferred-rank value wins over normal rank.
- **Box office:** keep worldwide-tagged values, or the only value when it has no region qualifier. Several worldwide values → the one with the latest point in time (no date → last).
- **Budget:** several values more than 2× apart → all dropped as ambiguous; otherwise preferred, else latest.

### Conversion

- Amount in currency C, release year Y → USD at `fx_rates.csv[C, Y]` → 2025 dollars with the existing CPI step.
- Currency not in `fx_rates.csv` → dropped (`wikidata_currency_dropped`).
- FRF, DEM, ITL, ESP: their own rates up to 1998; from 1999, the fixed euro conversion rate then the EUR rate.

### Combining with TMDB

| TMDB value | Wikidata value | Result |
|---|---|---|
| Good | none | TMDB |
| Missing or < $1,000 | yes | Wikidata, `money_source = wikidata` |
| Flagged suspect (currency or token box office) | yes, passes every check | Wikidata replaces it, flag cleared |
| Good | > 3× apart | TMDB kept, `money_suspect`, reason `wikidata_disagree` |
| Good | within 3× | TMDB, counted as confirmed |

Budget and revenue are combined separately, so a film can mix sources. Then the existing rules run on the final values whatever their source: < $1,000 → NULL, token box office (`LOW_RATIO`), the per-language currency cap, and the 182-day still-earning rule.

### Schema

- `movies.money_source_budget`, `movies.money_source_revenue`: `tmdb`, `wikidata` or NULL.
- `money_suspect` reasons gain `wikidata_disagree`.

### Report and tests

- Report lines: filled, replaced, confirmed, disagree-flagged, currency-dropped, region-dropped, ambiguous-budget-dropped, new films added.
- `tests/test_wikidata_clean.py`: a small fixed sample of statements covering every rule above; `tests/test_wikidata.py` for parsing and resume (no network).

## 3. Model: retune, compare, version 2

### Before the data changes

- Back up `data/movies.db` and `ml/artifacts/` as v1 (`*.pre_v15`).
- Run v1 (trained on ≤2015) over the validation and backtest films; save per-film predictions to `reports/v1_reference.json`.

### After the new data is in

1. Optuna retune for revenue, budget and score: same folds 1–2, same 15-minute limit per target.
2. Train v2 on ≤2015. Report:
   - **Like for like:** films in v1's validation and backtest sets that are still clean in v2 (films newly flagged `wikidata_disagree` leave both; their count is reported).
   - **All films:** including new ones, separately.
   - **Learning curve** again.

### Keep rule (validation and backtest only)

- Revenue: v2 lower than v1 on validation and on the backtest mean, like for like.
- Revenue coverage 77–83% on validation.
- Budget and score: no worse than v1 by more than the backtest std.

### If v2 passes

- Calibrate, retrain on 1960–2025, run the 2019+ test and the 2026 holdout once.
- `MODEL_CARD.md` v2: v1 and v2 side by side, films added per source, note that the 2019+ test was first opened on 2026-10-21.
- Docker memory < ~450 MB and startup measured.

### If v2 fails

- Restore both `movies.db` and `ml/artifacts/` from v1 (the app computes track records from the database at prediction time, so they move together).
- Record the result in the decision log in `docs/`.

## Out of scope

- More films by vote rank; bigger or different model types; US-domestic or single-country box office; currencies outside the fixed list; any automatic or scheduled Wikidata refresh.

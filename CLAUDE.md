# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A movie prediction app: a creator fills in a planned film's form and gets 10th/50th/90th percentile ranges for **budget**, **revenue** and **audience score** (TMDB `vote_average`), calibrated to ~80% coverage. Data is our own TMDB pull (79,199 films, 1960–2025). `ml/` holds the pipeline and `ml.predict.Predictor` (the single entry point for predictions); `backend/app/` is the FastAPI API over it (Day 8); `frontend/` is the React app (Day 10: the creator form; the results page is Day 11).

The work follows a day-by-day plan: `Movie Prediction App Detailed Plan, Days 1–5.md` and `Days 6–10.md`. `PROGRESS.md` holds each day's checklist, stats, "Changes from the plan" and "Surprises / inputs for Day N+1". Each day's step 0 updates the plan document with decisions made, the last step is wrap-up (README, `PROGRESS.md`, commit), and the user approves before a day is closed. `README.md` is the source of truth for reported numbers and Limitations; keep it in sync with what was actually measured.

## Commands

Requires uv and GNU make (Windows: ezwinports make). Python 3.11 only. The frontend needs Node 24 (npm 11).

```bash
make setup        # uv sync (default groups dev + ml: everything; the image installs runtime deps only)
make model        # download MiniLM ONNX model to ml/artifacts/minilm/ (once) + its 8-bit copy model_q8.onnx
make test         # uv run pytest (offline, no network needed; real-data tests skip without the database/models)
make test-fast    # -m "not slow and not real_data": ~15 s
make coverage     # pytest --cov (ml/ and backend/, lines + branches)
make data         # TMDB pull (needs TMDB_READ_TOKEN in .env) + build_db + features
make db           # rebuild data/movies.db from data/raw/ (DROPS the features table; run make features after)
make features     # features table + ml/features/feature_list.json
make tune         # Optuna, 15 min per target -> ml/artifacts/*_params.json, reports/experiments.csv
make train        # ml.models.calibrate then ml.models.train -> ml/artifacts/
make evaluate     # validation + breakdowns + backtest -> reports/ (never touches test)
make api          # uvicorn backend.app.main:app on :8000 with reload, docs at /docs (loads the real models, ~10 s)
make docker-build # scripts/slim_db.py + ml.features.build prebuilt -> build/, then docker compose build (backend + frontend)
make docker-run   # docker compose up -d --wait (API :8000, app :8080)
make smoke        # scripts/smoke.py --base-url $(URL) --web-url $(WEB) (defaults :8000 / :8080; WEB= skips the app); exits 1 on any failed check
make web-setup    # cd frontend && npm ci
make web          # Vite dev server on :5173, /api proxied to :8000 (run make api too)
make web-test     # cd frontend && npm run check: tsc -b (app + tests), oxlint, vitest run
make gen-api      # npm run gen:api: frontend/src/api/schema.d.ts from the running API's /openapi.json (commit it)
cd frontend && npm run coverage   # vitest with v8 coverage (shadcn's components/ui excluded)
uv run python -m ml.features.build prebuilt   # build/context.joblib: History/Companies/Franchises for the image
uv run python -m ml.eval.final all-data   # retrain the app's models on 1960-2025 -> ml/artifacts/final/
uv run python -m ml.explain.comparables   # comparables index -> ml/artifacts/final/comparables.npz (gitignored)
uv run python -m ml.predict manifest      # checksums of the app's files -> ml/artifacts/final/manifest.json
uv run python -m ml.data.pull --years 2026 --out-dir data/holdout_2026   # fresh holdout (needs TMDB_READ_TOKEN)
uv run python -m ml.eval.audit [validation|holdout|all]   # proper scores, bootstrap CIs, 2026 holdout -> reports/audit_metrics.*
```

`ml.eval.final test` was run once on Day 6 (`reports/final_test.md`) and refuses to run again. The git tags `pre-test` and `final-models` mark the frozen state before and after it.

Single test: `uv run pytest tests/test_models.py::test_name`. `tests/test_golden.py` runs `predict()` on the real all-data models (skipped without the database, `.joblib` files or comparables index) and compares with `tests/golden/predictions.json`; rewrite that snapshot only on purpose with `UPDATE_GOLDEN=1 uv run pytest tests/test_golden.py`. `tests/test_sanity.py` (same skip rule) checks logic rules on the real models: bounds, a monotone budget, invariance, the two revenue modes, form edges, matched-pair directions and train/serve date drift. `tests/test_api.py` tests every endpoint offline through `TestClient` with an injected small `Predictor` on the `db` fixture (`ENDPOINTS` pins each endpoint to its test, so a new endpoint fails until it is listed); `tests/test_api_golden.py` (same skip rule as the golden tests) runs the golden forms and real lookups over HTTP. Every module with a CLI runs as `uv run python -m ml.<pkg>.<module>`.

Test markers (`pyproject.toml`): `slow` (end-to-end, fuzz, real-database time travel) and `real_data` (needs `data/movies.db` and the app's models; also skipped automatically without them). `tests/test_e2e.py` runs the committed fake pull `tests/fixtures/mini_raw.jsonl` through every real step to HTTP (regenerate it with `uv run python -m tests.fixtures.mini_raw`; a test checks it is current). `tests/test_time_travel.py` cuts a database at a date and requires identical features for the deleted films. `tests/test_fuzz.py` (hypothesis, derandomized) sends random bodies to the predict endpoints: 200 or our 422, never 500. The golden forms live in `tests/golden/forms.json` (also read by `scripts/smoke.py`).

Not in git (rebuilt by the commands above): `build/` (the image's slim database and prebuilt context), `data/raw/`, `data/holdout_2026/`, `data/movies.db`, `data/overview_embeddings.npz`, `ml/artifacts/minilm/`, `ml/artifacts/*.joblib`, `ml/artifacts/final/*.joblib`, `ml/artifacts/final/comparables.npz`. The JSON settings/calibration/metadata in `ml/artifacts/` and everything in `reports/` are committed.

## Hard rules

- **Pre-release inputs only.** Post-release fields (`popularity`, `vote_count`, `vote_average`, `revenue`) are never features. The creator form in `ml/features/contract.py` defines every allowed input.
- **Time-based splits:** train ≤2015, validation 2016–18, test 2019+ (constants in `ml/data/clean.py`). The test split is locked: `ml.eval.splits.load(..., "test")` raises `TestSetLocked` unless `final=True`, and only `ml/eval/final.py` may pass it (enforced by `tests/test_final.py`). The test was opened once on Day 6; models must not be changed because of its results. Never fit, early-stop or calibrate on 2016–18 either; it is the honest check.
- **Leak safety** (tested in `tests/test_features.py`): only films released strictly before a film's date count; an earlier film's revenue/score counts only once it is 182 days old (its budget from release); top-N vocabularies, themes and PCA are fit on train years only; a film is a franchise film only if its collection already had an earlier entry.
- **Every model is compared with baselines B0–B2** through the same harness.
- TMDB `0` budget/revenue means unknown. Money is compared in 2025 dollars via `data/cpi_us_annual.csv` (add a row before pulling a new year).

## Architecture

Pipeline: `ml/data` (pull → clean → SQLite) → `ml/features` (one feature function → `features` table) → `ml/eval` (splits, metrics, harness) → `ml/models` (baselines, LightGBM, tuning, calibration).

- **`ml/data/`**: `tmdb_client.py` (rate-limited httpx client, ~20 req/s), `pull.py` (resumable discover + details pull to `data/raw/tmdb_movies.jsonl`), `clean.py` (all cleaning rules; bad values become NULL, suspect money is flagged, every released film is kept), `build_db.py` (builds `data/movies.db` with FTS, a `meta` table of build stats stored as JSON, and per-model training views `v_train_revenue` / `v_train_budget` / `v_train_score`).
- **`ml/features/build.py` is the single feature function** shared by training and the future API: `build_features(form, as_of, ctx)`. Training films are converted to creator forms with `film_to_form` and judged at their release date; a creator's film is judged at the 1st of its release month (`api_as_of`). Any new feature must go through this path so training and serving can't drift. Inputs come from `history.py` (track record with shrinkage toward the "typical film" as if 4 extra average films), `basic.py` (+ `vocab.json`), `themes.py` (+ `themes.json`), `synopsis.py` (MiniLM via `text.py`, PCA in `ml/artifacts/synopsis_pca.json`). `feature_list.json` records each feature's source and which models may use it (`NOT_ALLOWED` keeps a model's own target out).
- **`ml/eval/`**: `splits.py` joins a model's view with the features table (`load`, `fold_data`, three rolling-backtest `FOLDS`: ≤2009→2010–12, ≤2012→2013–15, ≤2015→2016–18). `evaluate.py` is the harness: any object with `fit(train_df)` and `predict(df) -> DataFrame[p10, p50, p90]` (in target units: log 2025 $ for money, points for score) gets validation metrics, breakdowns and the backtest. `metrics.py` holds MAE log / within 2× / coverage / width.
- **`ml/models/`**: `baselines.py` (B0–B2, ranges from train residuals), `train.py` (`LgbmQuantile`; revenue = monotone Huber middle in `MONOTONE` + quantile models of out-of-fold residuals without those columns, because LightGBM refuses monotone constraints on quantile objectives; budget = three unweighted quantile models (never sees `log_budget`); score = three weighted quantile models; `DEFAULT_DROP` is per target: synopsis out of every model, the budget track record also out of score; `EXCLUDED` keeps `log_budget` out of score), `tune.py` (Optuna on folds 1–2, tree count from early stopping), `calibrate.py` (our own CQR function, not MAPIE: widen ranges by q on both sides, learned on out-of-fold predictions from folds 1–2), `ablation.py`, `chain.py` (one revenue model with two corrections, "budget given" and "budget estimated" from the budget model; `predict_revenue(features, budget=None)`, `compare_budget`; `Chain.load(out_dir)`), `rough.py` (frozen rough-estimate cut-offs for revenue and budget).
- **`ml/explain/`**: `drivers.py` (`pred_contrib` on each middle model; contributions plus `expected` add up to the shown p50, crossed budget/score quantiles rescaled; strength cut-offs +50% / +20% for money, 0.3 / 0.1 points for score), `groups.py` (12 creator-friendly groups; every model feature must have one, synopsis has none), `sentences.py` (one template per group, filled from the clean form and feature row; never a raw feature name), `comparables.py` (`Index` of `score_ok` films; only films released strictly before `as_of`; weighted similarity incl. language; money films first).
- **`ml/predict.py`**: `Predictor.load()` checks `ml/artifacts/final/manifest.json` checksums, loads the chain, score model, `FeatureContext` (read-only DB, ~11 s) and comparables; `predict(form)` -> JSON-ready ranges, rough flags, budget comparison, drivers, comparables, warnings, `model_version`. A changed model file means a deliberate `ml.predict manifest` rerun and golden-snapshot update.
- **`backend/app/`** (FastAPI, everything under `/api/v1`): `main.py` has `create_app(settings, predictor, lookups)`; its lifespan hook loads the `Predictor` once and builds the in-memory autocomplete (`services/lookups.py`, names packed into byte blobs, ~33 MB), the prediction cache and the rate limiter onto `app.state`. `settings.py` reads `MOVIES_DB`, `MODELS_DIR`, `CORS_ORIGINS`, `RATE_LIMIT`, `CACHE_SIZE`. `deps.py` gives each request its own read-only SQLite connection (`mode=ro`, `check_same_thread=False`, because sync endpoints run in the thread pool). One router file per resource in `routers/` (a new endpoint = a new file, added to `ROUTERS`); `schemas/` are the Pydantic request/response models (strict types; the form's rules stay in `contract.validate`, never duplicated); `repo/` has read-only SQL only (FTS input is always turned into quoted prefix tokens); `services/` has the LRU prediction cache + compare, the sliding-window rate limiter and poster URLs. `errors.py` gives every 422 one shape, `{"detail", "errors": {dotted.field: message}}`, using the contract's messages where it has one.
- **Docker** (`backend/Dockerfile`, `docker-compose.yml` with the backend and the frontend, `.dockerignore` whitelists `pyproject.toml`, `uv.lock`, `ml/`, `backend/`, `build/movies.db`, `build/context.joblib`, and drops `ml/artifacts/*.joblib` and the full `model.onnx`): runtime deps only (`uv sync --no-default-groups`); `optuna`, `matplotlib`, `scikit-learn`, `onnx` are in the `ml` group, so the serving path must never import them at module level (sklearn imports live inside the training functions; `Chain.load` imports `calibrate` only for models without `q_estimated`). The image sets `CONTEXT_FILE` (prebuilt History/Companies/Franchises, stamped with the database's `built_at` and film count, refused on mismatch) and `MALLOC_ARENA_MAX=2`; the lifespan calls `release_free_memory()` (glibc `malloc_trim`). Memory gate: under 450 MB after 100 predictions in Docker (407 MB on Day 9). The app embeds a synopsis with `text.APP_MODEL` (8-bit, per-channel uint8); training and the comparables index use the full model. History's and Companies' name lookups are `NameMap` (packed sorted bytes), Companies/Franchises use `Groups` (offsets into flat arrays): keep new per-entity data in that packed form, not dicts of small objects.
- **`frontend/`** (Vite 8, React 19, TypeScript 6, Tailwind 4 + shadcn/ui on Radix, React Router 8, TanStack Query 5, React Hook Form + Zod 4; lint is oxlint): `src/api/` has the one typed client (`client.ts`: every failure is an `ApiError` with `kind` validation/rate_limited/not_found/network/server), the hooks (`hooks.ts`: options cached an hour, name search debounced 250 ms) and shared error handling (`errors.ts`: `notifyError` toasts 429/network/server, `applyFieldErrors` maps a 422 onto form fields); `schema.d.ts` is generated, never edited, and types come from it, so a backend schema change must be followed by `make gen-api`. `src/form/model.ts` holds the form values (`NameRef` = `{id, name}`, id null for a new name), the Zod rules built from `/meta/options` fields (`makeSchema`: never hard-code a limit the contract has) and `toApiBody`; `examples.ts` are the golden forms with names (a test requires they send exactly `tests/golden/forms.json`); `persist.ts` keeps the form in `?f=` (base64url JSON, validated field by field on load) and a localStorage draft (always try/catch). Name inputs (`inputs/NameSearch.tsx`) show suggestions only once the search for the current text is done, so Enter never picks a stale match or "new". `/predict` is lazy-loaded (its libraries are most of the bundle). Tests: Vitest + Testing Library in jsdom, `src/test/` has the setup (matchMedia, ResizeObserver stubs), `renderApp(path)`, `mockFetch` (offline) and `options.json` (the real `/meta/options`, kept equal to the contract by `tests/test_api.py`). `tsconfig.app.json` excludes the tests (the image's build checks the app only); `tsconfig.test.json` covers them for `npm run check`. `.npmrc` sets `legacy-peer-deps` (two optional peer chains npm 11 refuses; see the file). The frontend image (`frontend/Dockerfile`, context `frontend/`) builds with Node 24 and serves `dist/` with unprivileged nginx on 8080 (`nginx.conf`: client-side routes to `index.html`, `/api/` proxied to `backend:8000`).
- **`ml/eval/audit.py`** (after Day 7, `reports/audit.md` is the write-up): refits every model as `make evaluate` does and checks the numbers against `reports/metrics.json`, adds pinball loss, the interval score, R², bias and bootstrap intervals, and scores the all-data app models on the 2026 holdout (revenue and score only for films 182+ days old; baselines fitted on ≤2018). It never loads the test split.
- **`ml/eval/final.py`** ran the one-time test (≤2018 models, corrections from all three folds) and builds the app's all-data models in `ml/artifacts/final/` with the ≤2018 corrections; `Chain.load(ml/artifacts/final)` serves them. `ml/artifacts/` itself holds the ≤2015 models from `make train`.

## Conventions

- Module docstrings list the public API and the CLI; follow that style when adding modules.
- Tests use small fake TMDB records built with the real `trim_movie` (`tests/factories.py`); keep the suite offline.
- The plan and README are written in plain, short sentences with concrete numbers; changes from the plan are recorded in `PROGRESS.md`, not silently made.
